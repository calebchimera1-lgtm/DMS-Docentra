# Docentra Mobile (Flutter)

Android & iOS client for the Docentra Enterprise Document Management System.

## What's implemented

- Login (with optional organization slug) + TOTP/backup-code MFA challenge
- Session persistence and automatic access-token refresh on 401
- Personal dashboard (pending approvals/signatures, unread notifications)
- Document browsing by folder, folder creation, camera scan / gallery /
  file-picker upload
- Document detail: favorite, download + open with the OS viewer, check-out/in
- Offline mode: the last successful folder listing is cached to disk and
  shown (clearly marked) when the device has no connectivity
- Tasks tab: approve/reject workflow steps, sign/decline e-signature requests
- Notifications list with mark-as-read / mark-all-as-read

## Important: this repo ships Dart source only, not a buildable Flutter project yet

This environment does not have the Flutter SDK installed, so the native
`android/` and `ios/` platform folders (generated by `flutter create`) are
**not** included here — hand-writing hundreds of Gradle/Xcode boilerplate
files by hand is not practical or reliable. The `lib/` source, `pubspec.yaml`,
and `analysis_options.yaml` are complete and ready to drop into a scaffolded
project.

To get a runnable app, on a machine with the Flutter SDK installed:

```bash
cd mobile
flutter create --org com.docentra --project-name docentra_mobile .
flutter pub get
flutter run --dart-define=API_BASE_URL=http://<your-backend-host>:4000/api/v1
```

`flutter create .` will add the missing `android/`, `ios/`, `web/`, and test
scaffolding around the existing `lib/` folder without touching it.

## Configuration

The API base URL is compiled in via `--dart-define`:

```bash
flutter run --dart-define=API_BASE_URL=https://api.yourdomain.com/api/v1
```

Defaults to `http://10.0.2.2:4000/api/v1`, which reaches a backend running
on the host machine's `localhost:4000` from the Android emulator.

## Architecture

```
lib/
  core/
    api_client.dart     REST client: auth header injection, 401 refresh retry
    session.dart         In-memory + persisted (SharedPreferences) auth state
    offline_cache.dart    Last-known-good document listing per folder
    config.dart           API base URL (via --dart-define)
  models/models.dart      Lightweight DTOs (Document, Folder, Approval, ...)
  screens/                One file per screen, plain StatefulWidget + setState
```

No state-management framework (Provider/Riverpod/Bloc) was introduced —
screens fetch their own data with `ApiClient` and manage local UI state
directly, which keeps the surface small given this app covers a subset of
the full web feature set (RBAC administration, audit logs, executive
dashboards, and workflow-template authoring are web-only; the mobile app
focuses on the day-to-day mobile use cases: capture, review, approve, sign).
